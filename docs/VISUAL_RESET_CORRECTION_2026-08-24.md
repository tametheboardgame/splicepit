# SplicePit Visual Reset Correction — 24 August 2026

## Status

**HUMAN REJECTION / AUTHORITATIVE CORRECTION**

Human review on 24 August 2026 rejected the visible WP0.4E character-selection presentation.

The rejected presentation is the dark brown/olive monospace `APPRENTICE REGISTRATION` screen built from web-form controls, tabs, panels and a framed sprite preview. It accidentally recreated presentation language that the 23 August graphics-first reset had already superseded.

This correction is not a request to polish that screen. It is a direction to stop building from it.

## What survives

The following WP0.4E work remains useful technical infrastructure:

- the four protagonist IDs: Milo, Theo, Ada and Pip;
- accepted protagonist frame assets from WP0.4D;
- `avatarId` plus player-name state;
- name normalisation/validation;
- save/load persistence;
- backward-compatible hydration of older saves;
- keyboard-safe text capture;
- mouse/touch-capable input architecture where it remains presentation-independent.

## What is rejected

The following is explicitly **not approved** and must not be treated as visual canon:

- the `APPRENTICE REGISTRATION` page;
- dark terminal/console visual language;
- brown/olive admin-screen styling;
- large form-like screen composition;
- character tabs as the core visual metaphor;
- boxed live-preview presentation;
- visible HTML-form presentation as the default game boot;
- any claim that WP0.4E's visual gate passed merely because its technical browser tests passed.

Automated correctness does not constitute human visual acceptance.

## Corrected sequence

The immediate graphics-first sequence is now:

**accepted protagonist sprites → remove rejected boot presentation → build the concept-derived Apprentice Splicer Yard → establish real in-world scale/movement/camera language → redesign character choice to feel native to that game world → HUMAN PLAYTEST STOP**

The world must now establish the visual grammar before the final character-select presentation is locked.

## Temporary boot rule

Until the Yard exists, boot may use a deliberately temporary canvas-only visual-reset harness built around the accepted protagonists. It must:

- avoid the rejected terminal/web-form presentation;
- avoid routing into old Lab/Splice/Battle visuals;
- preserve identity persistence for technical validation;
- remain clearly disposable and non-canon;
- not become an excuse to delay the Yard.

The temporary harness is not a replacement visual direction and does not pass the later human character-selection gate by itself.

## Yard-first rule

WP0.4F is the next real visual build.

The Yard must be designed from the approved concept direction outward, with an accepted protagonist visibly present at provisional gameplay scale. Do not begin from the old Lab, and do not derive the new game's interface language from rejected forms/panels.

After the Yard and movement language exist, character selection is redesigned using that game's visual grammar. Candidate approaches may be in-world, scene-based, spatial or otherwise game-native. No specific candidate is locked before seeing the world.
