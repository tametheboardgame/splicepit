# SplicePit Work Packages — R3 / Content-Complete Beta

R3 assumes the intended major story/system/content set exists or is now being finished. The dominant mode changes from invention to completeness, balance, coherence and defect removal.

---

## WP3A — Content Completion and Canon Audit

**Depends on:** R2 accepted and final intended full-game content scope defined.

**Purpose:** Ensure every intended location, quest, NPC, Pit, animal, source package, upgrade and branch outcome is present and correctly marked canon.

**Deliverables:**
- content manifest versus implementation audit;
- missing authored content completed;
- prototype/draft assets removed from production paths or explicitly promoted;
- broken references/placeholder text/temporary economy values eliminated;
- story branch and ending requirements mapped to implemented content.

**Gate:** no known intended major content is absent and production manifests contain no accidental prototype dependencies.

## WP3B — Splicing, Knowledge and Biological Balance Pass

**Depends on:** WP3A.

**Purpose:** Balance the defining system across the full biological roster without eliminating uncertainty or experimentation.

**Deliverables:**
- outcome-band/variance distribution review;
- complexity/stability progression review;
- test-animal/material economy review;
- knowledge/diagnostic progression tuning;
- compatibility/epistasis exploit scan;
- mutation research value/risk tuning;
- rare/common source usefulness review;
- large seeded splice simulations and representative manual experiment paths.

**Gate:** no obvious deterministic optimal recipe or trivial infinite-testing/material exploit dominates; experimentation remains valuable from early to late game.

## WP3C — Combat, Arena and Pit Balance Pass

**Depends on:** WP3A–B.

**Purpose:** Balance full-game combat across Land/Water/Air, specialists/generalists and safe/high-risk Pit rules.

**Deliverables:**
- action economy/stamina/cooldown review;
- training effectiveness review;
- specialist/generalist matchup simulations;
- opponent AI/archetype tuning;
- injury/death risk review by Pit tier;
- Water/Air/Land environment balance;
- team/asymmetric/special-bout exploit review;
- headless simulation trend reports.

**Gate:** no universal dominant capability/action/build is evident and all intended circuit specialisations are viable.

## WP3D — Economy, Progression and Branch-Coherence Pass

**Depends on:** WP3A–C.

**Purpose:** Make the complete game economically and narratively coherent across major choices.

**Deliverables:**
- debt pressure versus exploration pacing review;
- buy/harvest/win/trade value comparison;
- pit-upgrade cost/order tuning;
- recovery/housing/transport friction tuning;
- creditor/free branch reward/access comparison;
- story-clock/deadline sanity checks;
- dead-end/soft-lock/excessive-grind audit;
- save-retry abuse review where it undermines intended risk.

**Gate:** all intended main routes can complete without unreasonable grind or hidden mandatory specialisation, and branch differences remain meaningful rather than cosmetic.

## WP3E — UX, Accessibility, Controller and Localisation Beta Pass

**Depends on:** WP3A–D.

**Purpose:** Ensure the game can be understood and operated without developer familiarity.

**Deliverables:**
- complete onboarding/tutorial clarity review;
- lab uncertainty/risk communication review;
- combat cause/effect readability review;
- keyboard remapping/controller coverage;
- focus/navigation audit;
- reduced shake/flash and non-colour-only communication checks;
- long-string/localisation layout stress tests;
- warning/disclaimer/rating presentation finalisation if not already locked.

**Gate:** no critical flow requires mouse-only/undocumented input, key information is accessible, and localised-length fixtures do not break core UI.

## WP3F — Browser Performance, Asset and Compatibility Beta Pass

**Depends on:** WP3A–E.

**Purpose:** Remove scale/performance problems before release-candidate freeze.

**Deliverables:**
- supported browser/device matrix;
- initial load/bundle/asset timing review;
- phenotype rendering/cache/memory profiling;
- large-save load/save profiling;
- long-session scene-transition/memory tests;
- asset compression/loading optimisation;
- fallback/error behaviour for missing/failed audio/assets;
- Cloudflare deployment regression checks.

**Gate:** documented supported targets run the complete game within accepted performance budgets and no known memory/save growth issue threatens long sessions.

## WP3G — Full-Game Beta Regression and Feature Freeze Gate

**Depends on:** WP3A–F.

**Purpose:** Prove a content-complete build can repeatedly finish before entering release-candidate mode.

**Deliverables:**
- repeated fresh-save full-game playthroughs covering major branches/specialisations;
- automated regression suite expansion at key chapter/branch checkpoints;
- old-save migration tests from supported Alpha versions;
- severity-ranked defect backlog;
- explicit decision on which defects block RC;
- feature requests deferred unless necessary to fix a blocker.

**Gate:** no known blocker prevents full completion from fresh or supported migrated saves; development formally enters feature freeze except blocker-driven changes.

### R3 release gate

The game is content-complete and repeatedly finishable. Remaining work is release stability, compatibility, legal/asset closure and severe-defect elimination rather than feature development.
